Q3. Does it take the same amount of work to compute `isPerfect` on the number 10 as it does on the number 1000? Why or why not? Does it take the same amount of work for `findPerfects` to search the range of numbers from 1-1000 as it does to search the numbers from 1000-2000? Why or why not?
A3. No, it does not take the same amount of work to compute `isPerfect` on the number 10 as it does on the number 1000. isPerfect calls divisorSum, which loops from 1 to n−1, so isPerfect(10) runs about 9 iterations and isPerfect(1000) runs about 999. Larger numbers take more work because the function is checking through more divisors that come before it. 2nd part: No. Both ranges have 1000 numbers, but each number in 1000–2000 needs more loop iterations (because larger numbers = more divisors logic) to check than each number in 1–1000.

Q4. Extrapolate from the data you gathered and make a prediction: how long will it take `findPerfects` to reach the fifth perfect number?
A4. Doubling the search size made the runtime go up by about 4 times, so the time grows with the square of the search size. Q5. Do any of the tests still pass even with this broken function? Why or why not?
A5. Yes, all the negative tests passed. Since total starts at 1, divisorSum returns 1 for every negative number, because the loop never runs. As a result, isPerfect always returns false, since a negative number never equals 1. This means that even with the broken function, the tests pass without ever actually checking whether the number is negative.

Q6. Explain your testing strategy for `smarterSum` and how you chose your specific test cases that lead you to be confident the function is working correctly.
A6. I tested smarterSum by comparing its results to divisorSum, since divisorSum is already known to be correct. I used perfect squares like 25 and 36 to make sure the square root isn't counted twice. I tested 1, 0, and a negative number because those are edge cases where the loop might not run. I also tested a prime and some perfect numbers to make sure the divisor pairs add up correctly.

Q12. Think about one or more examples of a class of names that the Soundex system might not work well for. Explain what this class of names is and why the system might incorrectly group them or mis-categorize one of the names.
A12. Names that have different spelling but differen pronounciations. Because Soundex classifies and makes a new code for a name based on its original spelling, it doesn't consider the different ways a name is spelled in different regions of the world or different time periods, which might change the original soundex code of the name, resulting in inaccurate matches when we do soundex search. For example in the Daitch–Mokotoff Soundex it considers the way Slavic names uses greater accuracy in matching names with similar pronounciations but different spellings representing a larger sample of the world population.
